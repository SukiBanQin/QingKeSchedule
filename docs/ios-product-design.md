# 课表软件 iOS MVP 产品设计文档

## 1. 产品概述

iOS 版是现有 Web 课表软件的移动端延伸，面向需要随时查看个人课表的学生。首个版本只支持 iPhone，重点解决“快速查看今天的课程”“在手机上管理课表”和“及时收到上课提醒”三个问题。

iOS 版保留 Web MVP 的课程模型和核心业务规则，但根据手机屏幕和移动使用场景重新组织页面，不直接照搬 Web 界面。应用以本地、离线使用为主，暂不依赖账号和网络服务。

## 2. 与 Web 版的关系

- Web 版继续保留并可独立使用，不被 iOS 版替代。
- 两端使用一致的学期、节次、课程和上课安排定义。
- 首版不提供两端实时同步，用户在某一端的修改不会自动出现在另一端。
- 两端采用兼容的数据文件格式，方便将 Web 版已有课表导入 iOS，并为后续同步能力打基础。
- Web 端需要在后续增加兼容的数据导出能力，但不改变原有核心使用流程。

## 3. 产品目标

- 用户打开应用后，可以立即看到今天还有哪些课程。
- 用户可以在 iPhone 上完成学期设置和课程管理。
- 每周、单周、双周及一门课程的多个上课安排能够正确展示。
- 用户可以在上课前收到可靠的本地提醒。
- 无网络时仍可正常查看和编辑课表。
- 用户可以迁移和备份本地课表数据，降低重复录入和数据丢失风险。
- 保持首版范围简单，为提醒、组件和云同步等能力留出迭代空间。

## 4. 目标用户与使用场景

目标用户为已经使用或准备使用个人课表工具的学生。

主要使用场景：

- 上课前快速确认下一门课程的时间和教室。
- 在应用未打开时，通过系统通知获知即将开始的课程。
- 查看今天全部课程及其当前状态。
- 查看本周或其他教学周的课程安排。
- 新学期录入学期信息和课程。
- 临时发现课程信息有误时，在手机上修改。
- 将 Web 版课表导入 iPhone，或导出文件进行备份。

## 5. iOS MVP 功能范围

### 5.1 首次使用

- 首次启动时提供简短引导。
- 用户可以选择手动创建新课表，或从兼容的数据文件导入。
- 尚未配置学期时，引导用户先设置学期，再添加第一门课程。

### 5.2 今日课程

- 作为应用默认首页，按时间顺序展示当天课程。
- 展示课程名称、节次、具体时间、教师和教室。
- 区分已结束、正在进行和尚未开始的课程。
- 突出显示下一门课程。
- 当天无课时展示清晰的空状态。

### 5.3 周课表

- 按教学周展示完整课表，并默认定位到当前周。
- 支持切换上一周、下一周以及返回当前周。
- 支持每周、单周和双周课程的正确显示。
- 周课表适配手机小屏，可通过滑动查看不同日期或课表区域。
- 点击课程卡片可以查看课程详情并进入编辑。

### 5.4 课程管理

- 新增、编辑和删除课程。
- 记录课程名称、教师、颜色等基本信息。
- 一门课程可以包含多个上课安排。
- 每个安排包含星期、起止节次、起止周、重复规则和教室。
- 发现课程时间冲突时给出提示，但允许继续保存。
- 编辑默认作用于整门课程，不支持只修改某一次课程。

### 5.5 学期设置

- 设置学期名称、开始日期和总周数。
- 设置每日节次及对应的开始、结束时间。
- 根据开始日期自动计算当前教学周。
- 首版只管理一个当前学期。

### 5.6 上课提醒

- 使用 iOS 本地通知，不依赖网络即可提醒。
- 提供提醒总开关，首次开启时请求系统通知权限。
- 用户可以设置统一的提前提醒时间，默认提前 10 分钟。
- 通知内容包含课程名称、上课时间和教室。
- 新增或修改课程后自动更新相关提醒，删除课程后取消相关提醒。
- 关闭提醒或系统权限不可用时，不再安排新通知，并向用户说明当前状态。
- 首版不提供每门课程单独设置、多次提醒和自定义通知声音。

### 5.7 本地数据与迁移

- 学期和课程数据保存在设备本地。
- 关闭或重新启动应用后，数据保持完整。
- 支持从“文件”应用选择兼容的课表数据文件并导入。
- 支持通过系统分享面板导出课表备份文件。
- 导入前检查文件格式，并明确提示导入成功或失败。
- 暂不提供账号、云端备份和多设备自动同步。

## 6. 页面与导航结构

应用采用底部导航，包含三个主要入口：

1. **今日**：默认首页，展示当天课程和下一门课程。
2. **课表**：展示周课表并切换教学周。
3. **设置**：管理学期、节次、上课提醒以及数据导入导出。

课程详情和课程编辑通过页面跳转或系统式弹出页面进入。新增课程入口应在“今日”和“课表”页面中保持容易找到。

## 7. 核心业务规则

- 教学周从学期开始日期所在周算作第 1 周。
- 单周和双周按教学周编号判断，不按自然日历周判断。
- 课程时间以统一设置的节次为准，不为每门课程单独设置任意时间。
- 暂不处理节假日停课、临时调课、补课和特殊校历。
- 删除课程前需要二次确认。
- 课程冲突只提示，不强制阻止保存。
- 只为当前学期内尚未发生的课程安排通知；课程数据发生变化时，提醒应同步更新。
- 用户拒绝通知权限后，应用仍可正常使用，并提供前往系统设置开启权限的说明。
- 导入数据时，应由用户确认是替换当前数据还是取消导入，避免意外覆盖。
- 卸载应用可能导致本地数据丢失，应在数据设置中提示用户定期导出备份。

## 8. 体验与视觉方向

- 采用符合 iOS 使用习惯的导航、表单、日期选择和确认交互。
- 以竖屏使用为主，优先保证单手查看和操作。
- 今日课程强调信息层级，让时间、课程名称和教室能够被快速识别。
- 周课表保留不同课程的颜色区分，同时保证文字对比度和小屏可读性。
- 表单尽量提供默认值和选择控件，减少键盘输入。
- 适配系统安全区域、动态字体和浅色、深色外观。
- 空课表、无课、导入失败等状态均提供明确说明和下一步操作。

## 9. MVP 暂不包含

- 主屏幕或锁屏小组件、实时活动。
- Apple Watch、Siri 和快捷指令支持。
- 登录、账号体系、云同步和多人共享。
- 教务系统、图片或 OCR 课表导入。
- 临时调课、停课、补课和节假日校历。
- 作业、考试、成绩和学习计划管理。
- iPad 专用界面、Mac、Android 和桌面端应用。
- 复杂主题与个性化功能。

## 10. MVP 验收标准

- 用户能够手动创建学期和课程，并在重新启动应用后继续使用。
- 用户能够导入兼容的 Web 课表数据，并正确查看导入结果。
- 今日课程与周课表中的课程信息保持一致。
- 每周、单周、双周及多个上课安排均在正确日期显示。
- 新增、修改和删除课程后，相关页面立即更新。
- 课程冲突能够被识别并提示。
- 开启提醒并授权通知后，用户能够在设定时间收到包含正确课程信息的通知。
- 修改、删除课程或关闭提醒后，旧的课程通知不会继续触发。
- 无网络环境下，查看和编辑课表不受影响。
- 核心流程在计划支持的 iPhone 和 iOS 版本上通过测试。

## 11. 后续迭代方向

首版稳定后，可优先考虑每门课程的独立提醒、多次提醒、主屏幕组件、特殊校历和临时调课。随后再根据实际使用情况评估账号、云同步、多设备协作以及 iPad 和其他移动平台支持。
