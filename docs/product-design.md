# 课表软件 Web MVP 产品设计文档

> 状态：旧 Web MVP 已从当前工作树移除，完整实现可从 Git 标签 `pre-ios-web-restructure` 恢复。本文档作为历史设计资料保留；`web/` 目录等待未来重新设计。

## 1. 产品概述

这是一款面向学生的个人课表工具。首个版本以 Web 端为载体，帮助用户快速录入课程，并清楚查看今天和本周的课程安排。

MVP 只解决“创建课表”和“查看课表”两个核心问题，不加入提醒、社交、教务系统接入等扩展能力。产品的数据结构和业务规则应为后续手机 App 复用留出空间。

## 2. 产品目标

- 用户可以在几分钟内完成学期与课程设置。
- 用户打开产品后，可以立即知道今天和本周要上的课程。
- 正确处理起止周、单周、双周以及一门课程的多个上课安排。
- 数据在当前浏览器本地保存，刷新或关闭页面后不会丢失。
- 功能和交互保持简单，为后续迭代保留清晰边界。

## 3. 目标用户与使用场景

目标用户为需要管理固定学期课程的学生。

主要使用场景：

- 新学期开始时，设置教学周和每日节次。
- 录入、修改或删除课程。
- 每周查看完整课程安排。
- 上课当天查看剩余课程、时间和地点。
- 切换教学周，确认单双周课程。

## 4. MVP 功能范围

### 4.1 学期设置

- 设置学期名称、开始日期和总周数。
- 设置每日节次及对应的开始、结束时间。
- 根据学期开始日期自动计算当前教学周。
- MVP 只管理一个当前学期，教学周按连续自然周计算。

### 4.2 课程管理

- 新增、编辑和删除课程。
- 记录课程名称、教师、颜色等基本信息。
- 一门课程可以包含多个上课安排。
- 每个上课安排包含星期、起止节次、起止周、重复规则和教室。
- 重复规则支持每周、单周和双周。
- 编辑课程时默认修改该课程的全部安排，不支持只修改某一次课程。

### 4.3 周课表

- 按“星期 × 节次”的网格展示课程。
- 默认进入当前教学周，并突出今天。
- 支持查看上一周、下一周以及返回当前周。
- 课程卡片展示课程名称和教室，点击后可查看或编辑详情。
- 发现时间冲突时给出提示，但允许用户继续保存。

### 4.4 今日课程

- 按时间顺序展示当天课程。
- 展示课程名称、上课时间、教师和教室。
- 区分已结束、正在进行和尚未开始的课程。
- 当天无课时展示明确的空状态。

### 4.5 本地数据

- 学期设置和课程数据保存在当前浏览器中。
- 页面刷新或浏览器重启后，数据仍可恢复。
- 无需登录即可使用。
- MVP 暂不提供跨浏览器或跨设备同步。

## 5. 页面结构

Web 端首版包含以下页面或功能区域：

1. **周课表页**：默认首页，用于查看和切换每周课表。
2. **今日课程页**：集中展示当天课程状态。
3. **课程编辑页**：新增、编辑和删除课程及其上课安排。
4. **学期设置页**：配置学期、教学周和每日节次。

首次使用且尚未配置学期时，引导用户先完成学期设置，再录入第一门课程。

## 6. 核心业务规则

- 教学周从学期开始日期所在周算作第 1 周。
- 单周和双周按教学周编号判断，不按自然日历周判断。
- 课程时间以节次为准，不允许每门课程单独填写任意时间。
- 暂不处理节假日停课、临时调课、补课和特殊校历。
- 删除课程前需要二次确认。
- 课程冲突只提示，不强制阻止保存。
- 清除浏览器数据可能导致课表丢失，界面中应向用户说明这一点。

## 7. 体验与视觉方向

- 整体风格简洁、清晰，以课表内容为视觉重点。
- 不同课程使用颜色区分，同时保证文字有足够对比度。
- 课表网格在常见桌面浏览器中完整易读，并兼顾手机浏览器的基础可用性。
- 新增课程流程尽量集中在一个页面完成，减少不必要的跳转。
- 空课表、无课、数据错误等状态都应提供明确提示和下一步操作。

## 8. MVP 暂不包含

- 上课提醒和系统通知。
- 登录、账号体系和云同步。
- 教务系统、图片或 OCR 课表导入。
- 数据导入、导出与备份。
- 作业、考试、成绩和学习计划管理。
- 临时调课、停课、补课和节假日校历。
- 好友课表、分享和社交功能。
- 主题、桌面组件和复杂个性化设置。
- 原生桌面端与手机 App。

## 9. MVP 验收标准

- 新用户能够完成学期设置并成功创建课程。
- 每周、单周和双周课程能在正确的教学周显示。
- 一门课程的多个上课安排均能正确展示。
- 周课表和今日课程显示一致。
- 课程新增、修改和删除后，所有相关页面立即更新。
- 课程冲突能够被识别并提示。
- 刷新和重新打开页面后，本地数据保持完整。
- 核心流程在主流现代浏览器中可正常使用。

## 10. 后续迭代方向

MVP 稳定后，可优先考虑数据导入导出、特殊校历和临时调课，再评估提醒、账号与云同步。手机 App 可以复用相同的课程模型与业务规则，并根据移动端场景补充通知和桌面组件能力。
