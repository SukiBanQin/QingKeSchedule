## 基准与结论

- iOS `AppearanceMode` 固定为 `system`／`light`／`dark`，默认及未知值回退 `system`；生产环境保存到
  `UserDefaults`，App 根部通过 `preferredColorScheme` 即时应用。
- iOS 只在已有学期的设置页显示 `06 外观 / DISPLAY`，位于 `05 数据备份` 之后、底部保存卡片之前；首次设置页
  不显示外观入口，但仍消费已保存或系统外观。
- 三个按钮为 `AUTO 跟随系统`、`LIGHT 浅色`、`DARK 深色`。选中项有反相背景、黄色底线和“已选择”语义；
  下方显示实际解析结果“当前显示：浅色／深色”，因此跟随系统时文字显示当前系统真正采用的明暗，而不是“自动”。
- iOS 在无障碍大字号时把三个选项从横排改为竖排。Android 应采用等价的响应式布局，而不是复制 SwiftUI API。
- 以上行为足以确定 Android 首版 A11，**没有需要用户先决定的新产品规则**。

## Android 已有基础

- `AppearanceMode.SYSTEM／LIGHT／DARK`、`appearance_mode` DataStore 键、默认值和未知值回退已经存在；偏好仓库已有
  往返、损坏恢复、失败／取消、并发更新和关闭重开测试。
- `ScheduleAppState` 会与课表写入共用互斥边界，偏好写入成功后才发布完整新快照；失败恢复旧偏好并显示既有全局
  错误，不会改变课表。
- `QingKeAppContent` 已把三态解析为实际 `dark`：强制深色、强制浅色或 `isSystemInDarkTheme()`；主壳、首次设置、
  今日、周表、课程编辑、学期／日历／提醒／备份、弹窗和系统栏均消费该主题体系。现有 Compose 测试已大量覆盖
  浅色、深色、130% 字号、窄屏和不透明弹窗。
- A10 已证明 JSON 导入不覆盖外观，导出也不包含外观；D01 无需改变。

## 实施缺口与允许范围

1. `QingKeAppActions` 和 `ScheduleViewModel` 尚无外观更新入口。新增单一 `setAppearanceMode(mode)` 路径，复用
   `ScheduleAppState.updatePreferences`；相同值无操作，成功后才发布并即时重组主题，失败／取消保留原模式。
2. `SemesterSettingsScreen`／`TerminalSemesterForm` 尚未渲染 `06 外观`。新增一个共享终端风格分区，仅接入正式
   设置页，放在 `05 数据备份` 后、保存卡片前；不得出现在首次设置页。
3. 分区提供三态选择和实际显示文字。普通宽度横排；320dp、字体放大或内容不足时必须安全换为竖排或其他不裁切
   的等价布局。每项保持至少 48dp 触控目标、明确中文标签、单选／已选择语义和稳定 test tag。
4. 当前实际明暗必须由与 App 根主题相同的解析结果驱动；切换 LIGHT／DARK 后立即更新，SYSTEM 在系统夜间模式
   变化时自动更新。不得维护第二份可能漂移的“实际外观”状态。
5. 保持现有品牌色、课程色、终端层级与方角样式；只修复 A11 验证暴露的真实主题可读性问题，不借机重做已验收
   页面或扩大业务功能。

允许修改 `Android/` 中 A11 所需的 ViewModel、Compose UI、测试，以及 `docs/Android/` 的实施、证据与状态文档。
不得修改 iOS、Web、共享 JSON schema／fixtures、Room schema、DataStore 键或存储值、A08 提醒语义、A10 协议、
A11 以外功能、发布配置或 `main`。

## 验收条件

### 状态与持久化

- 默认／未知存储值为跟随系统；三态选择写入既有 `appearance_mode`，关闭重开和进程重建后保持。
- LIGHT 与 DARK 不随系统夜间模式变化；SYSTEM 随系统明暗切换并即时更新页面和“当前显示”。
- 相同选项不重复写；写入中不能产生相互覆盖的重复选择。失败显示既有中文错误，选中项、实际主题和持久化值均
  保持最后一次成功状态；取消不误报成功。
- 外观修改不触发提醒重算，不改变课表、教学日历、提醒偏好或传输状态。

### 界面与无障碍

- 正式设置页顺序为 `04 上课提醒` → `05 数据备份` → `06 外观` → 保存卡片；首次设置页没有 `06` 入口。
- 三个选项的文字、代码、选中视觉、单选语义和实际显示文字与 iOS 基准一致；浅色、深色和跟随系统两种系统状态
  均可读，系统状态栏／导航栏图标与实际表面保持可辨。
- API 37 实际检查设置页三态即时切换；覆盖 320dp 窄屏、至少 130% 字号及 Android 无障碍大字号布局，不裁切、
  不重叠、可滚动、触控目标不小于 48dp。
- 用固定同数据抽查 TODAY、课表、设置、课程编辑和至少一个弹窗，确认强制浅色／深色及 SYSTEM 的实际主题一致，
  不出现局部仍跟随系统或硬编码导致的不可读内容。

### 测试与证据

- JVM：ViewModel 相同值、成功、失败、取消／并发边界；证明只改变 `appearanceMode`。
- Compose／设备：分区顺序与首次设置缺席、三态选中及语义、实际显示文字、即时主题变化、窄屏／大字号、写入中
  防重复与失败保留原主题。
- API 37 生产 APK：系统 light／dark 下验证 SYSTEM，再分别强制 LIGHT／DARK；至少做一次 force-stop 重开证明
  持久化，并保存命令记录、设备属性、关键截图和 FATAL／ANR 检查。
- 完成 Debug／Release JVM、完整 `connectedDebugAndroidTest`、Debug／Release／AndroidTest 构建、lint、Android
  文档测试和 `git diff --check`；实际数量和任何环境限制如实记录。
