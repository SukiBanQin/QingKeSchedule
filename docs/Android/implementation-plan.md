## Codex 回退时的模型与思考档位建议

这是项目工作建议，不是模型能力的固定换算或正确性保证。2026-09-14 的旧流程（仅供回退）为 Sol 主 Agent 协调、一个明确指定的 Terra 执行子 Agent 实施；常规子任务固定使用 `gpt-5.6-terra`／`medium`，已有明确档位约定时保留。主 Agent 的实际模型身份和全局设置不能由子 Agent 工具读取或修改，仍以用户在界面中的选择为准。其他模型或档位调整必须先说明并由用户决定。

| 模型 | 思考档位 | 适用任务 |
| --- | --- | --- |
| Sol | 中 | 整理进度、解释文档、日常方案分析和生成明确任务 |
| Sol | 高 | 复杂任务可直接在执行窗口分析并实施；也用于独立代码审查、跨端一致性和验证证据分析 |
| Astra | 中 | Sol 多轮仍未定位的疑难问题，提供聚焦复现和已有证据后再升级 |
| Astra | 高 | 重大架构争议、复杂数据一致性或通知并发等需要更深入分析的少数任务 |
| Terra | 低 | 范围小且规则明确的文案、颜色、间距等修改 |
| Terra | 中 | 工程初始化、常规页面、表单、业务规则、测试及一般功能实施 |
| Terra | 高 | 边界清楚但推理较多的实施；复杂迁移和多组件联动优先考虑 Sol／高，不必逐档尝试 |

审查聚焦本次改动及相关依赖；修正复审重点验证原问题和可能回归。只有新证据、失败或未解决风险才扩大范围，不每轮无理由重读整个项目或重跑全部检查。满足验收条件后结束本轮，不持续加入无关优化。降低模型单价不保证每项任务必然更省，返工、上下文和实际推理量都会影响消耗。

选择理由应说明任务的歧义、关联范围和出错影响。高档不能弥补缺失的用户决定，也不能替代测试。反复失败时先整理错误、复现和已尝试方法，判断原因，再建议升档；没有依据时不一律升高，也不长期让低档承担所有功能。

Luna 仅在已有独立、明确的小任务时使用，不为凑齐角色增加窗口。建议和实际使用情况分开记录，未获得实际设置证据时写“未核实”，不推断服务商是否正确应用参数。

## 阅读与接手续接

采用根目录的增量阅读规则：同一窗口复用已读未变内容；有其他窗口提交或未提交修改时，只核对相关变化。首次接手、切换服务或压缩后缺少细节时，恢复最新任务状态并定向补读，不默认把所有基线、设计、历史审查和测试源码重新输出。

任务交接说明当前入口、必要章节和基准即可；相关源码按实际依赖定位。完整阅读某个文件必须有任务原因，不能把长清单作为每轮固定前置步骤。审查仍核对实际 diff 和证据，不把“已经读过”当作验证通过。无需用户手工跟踪读过哪些文件。

```text
先检查 Git 状态，保留已有改动；按任务约定由执行或分析窗口更新交接记录。
```

任务应覆盖一个能独立检查的结果，提供相关上下文，不反复复制整个聊天。执行窗口有疑问时，先核对文档与代码，再把影响范围的未决事项交回分析窗口。

## Codex 回退模式：Sol 主 Agent 与 Terra 执行子 Agent

用户主要与 Sol 主 Agent 对话。主 Agent 分析、定界、协调和审查，不直接修改应用代码；明确授权的文档更新及其验证除外。应用实施交给至多一个 Terra 执行子 Agent，共享工作区始终只允许一个写入者。

1. 主 Agent 只对用户已授权且边界清楚、适合独立实施的任务自行委派；不能从计划表推导新授权，也不能自动进入下一阶段。内部任务说明写明基准、必要上下文、允许路径、验收、提交和禁止事项。
2. 创建时显式指定 `gpt-5.6-terra` 和 `medium`，已有明确 `high` 约定则保留；新 Agent 接收必要任务上下文，不默认继承完整聊天，并明确禁止子 Agent 再创建子 Agent。若工具不能精确应用这些参数，停止委派并报告，不用普通聊天窗口或其他模型冒充。
3. 同一时刻最多一个执行子 Agent。同一任务的首次实施、修正和复审反馈优先复用同一 Agent；独立任务结束且关联较少时，在记录提交、验证和限制后可以中断旧 Agent 的活动轮次并创建新的，不必等完整阶段结束。
4. 当前协作工具的中断操作只停止正在运行的轮次，Agent 保持可复用；没有永久删除或保证释放的操作。因此“停止／关闭／释放／删除”均以工具返回为准，并准确区分已中断、仍可复用和不存在。
5. Terra 实施时主 Agent 不同时写文件，可并行做不重复实施的只读分析。Terra 必须回报实际提交范围、测试证据和限制；主 Agent 检查实际 diff，不能只采信摘要。
6. 小范围、低风险且验证充分的修改可直接交付；完整模块、数据迁移、通知、共享协议、工具链变更以及用户指定的审查必须独立审查。产品验收仍由用户确认。
7. 原人工执行窗口保留为备用，不删除或自动操作。仅当子 Agent 不可用、用户明确选择人工交接或切换官方／中转站时使用；切换前保存交接并停止原写入，不假定子 Agent 会话可跨服务迁移。
8. 先观察实际任务总消耗、返工、重复阅读和交接次数，再调整流程；不承诺固定节省额度，也不把官方额度百分比换算成中转站 token 价格。

### 完整实施后集中审查

默认流程：执行窗口一次明确目标、关键约束和验收条件 → DeepSeek 完成一个可独立验收任务的阅读、全部相关代码修改、测试、普通失败修复、界面／设备验证、证据、进度文档和提交推送 → 需要独立审查时 Sol 集中检查整个 diff 与证据。派发时写明完整交付边界及阻塞回报条件，不拆成“每改一个文件先请 Sol 检查”。现有范围限制、关键独立验证和用户验收不变。

DeepSeek 的普通进度、单文件完成或一次测试失败不触发审查。Sol 审查窗口 不中途轮询 diff 或重复排查；等待完成或阻塞通知，避免高频查同一状态。运行时唤醒或用户要求进度时简短回应，不顺便启动一轮审查。只在产品决定未定、必须扩大授权、关键架构冲突或反复排查仍不收敛时提前介入，接收必要证据；用户新反馈与真实风险仍及时处理。

最终审查集中列出有依据的修正项，由同一个 DeepSeek 完整修正；复查聚焦问题及相关回归，必要时独立运行针对性验证，不默认重复全部测试。一个完整功能／修正就是合适边界，不等整个 P3 结束。DeepSeek 实际参数由用户在客户端选择，不调整全局设置。

### 子 Agent 查找、复用与重建

同阶段高度相关的任务优先续接已有 Terra。派发前先查当前主会话的 Agent 列表，核对本任务交接保存的标识；列表未显示不是已失效的证明。若工具支持且确认属于当前主会话，再尝试按标识续接或恢复，附带期间变化和本次授权范围。不能把无错误返回当作缓存命中的证据。

创建后在当前任务交接中简记：Agent 标识、所属主会话／服务、负责范围、实际指定的模型／档位、最后一次工具确认的状态。未知项如实注明；复用、停止和跨服务交接时更新，不维护每轮调用流水账。主会话未知或不匹配时，不向其他会话的标识盲目发送任务。

completed 表示上轮完成，不等于不可续接；间隔一两小时或主窗口忘记标识都不能单独触发重建。缓存未命中也不是重建理由。只有旧 Agent 已确认不可访问或无法继续、任务关联明显降低，或上下文确有不适用证据时，才简述原因并创建替代者。若工具没有恢复接口，不声称已尝试恢复，记录实际查询或续接结果。

无法确认旧 Agent 是否仍在执行时，先核对运行与写入状态；未确认停止写入前不启动另一个写入者。跨官方／中转站不假定标识可以迁移。找不到可复用 Agent 时仍按增量阅读恢复必要资料，不重新全文加载项目。

## 需要独立审查时的推进

用户可以说“DeepSeek 执行完毕，请审查”。建议附任务编号、提交编号（多个提交提供范围）和执行结果摘要。未提供时，分析窗口先从当前仓库和交接记录定位；无法唯一确定范围时再询问，不把最新一个提交自动视为整个实施结果。

主 Agent 检查实际 diff、任务验收条件、测试及构建证据、遗留限制和已有改动。必要时执行相关验证；只读到测试源码或执行者自述不能等同于独立验证。审查结束记录范围、结论和下一步：

- 有问题：优先把具体修正反馈给原 DeepSeek 执行窗口；通过人工交接块集中回传。
- 证据不足：列出待验证项，不能将任务标记为已通过。
- 审查通过且无阻塞：有已授权后续任务才给出实施提示词；否则报告本轮完成，不制造任务。
- 涉及待定产品决定或范围变化：说明具体影响，先解决决定，再生成依赖该决定的任务。

审查一个任务通过，不代表整个阶段或产品验收完成。主 Agent 可以继续协调已授权任务，但不自动实施、不开启未授权任务，也不因 DeepSeek 自述“执行完毕”跳过审查。

推荐回传模板：

```text
DeepSeek 已完成任务：
提交编号／范围：
执行结果与测试摘要：
未完成项或限制：
实际模型／档位（如已知）：
请核对代码和证据并审查；有问题给修正提示词，通过后仅在存在已授权后续任务时给下一项提示词，不修改应用代码。
```

## 防止状态失真

- “已实现”需要代码依据，“已验证”需要命令／设备与结果，“已审查”需要审查范围；三者不自动推出“用户已验收”。
- 文档所列命令不等于已经执行。失败、未运行、环境不具备分别记录。
- iOS 基准后续变更、发现缺陷、范围增减和协议决定应在功能清单及交接中同步更新。

## 最终回复与人工备用交接

当前通过人工按需交接；仅恢复 Codex 子 Agent 模式后内部派发由主 Agent 完成。最终回复只简述目标、进度、结果、证据、限制和需要用户决定的事项，不重复内部完整提示词，也不承诺工具调用记录不可见。下列模板用于执行与审查窗口间的必要交接或服务切换；实际需要人工转交时，末尾只放一个填完整的交接块，并在块外写清接收窗口、模型和档位。

模型应填入实际任务、提交或范围、相关文件与验证情况，不保留 `XXXX` 或待用户填写的占位符。未运行、未提交、未知实际模型设置等情况如实标注。不要重复整段历史，把详细依据留在仓库供接手模型读取。说明文档使用中文；技术名称、代码标识和命令可保留原文。

## 本地提交与 GitHub 上传

正式仓库为 [QingKeSchedule](https://github.com/SukiBanQin/QingKeSchedule)。相关验证通过后，提交本任务文件，再推送当前分支到 `origin` 同名分支；核对远程 HEAD 后才记录上传成功。首次推送设置 upstream，后续仍核对目标。禁止自动合并到 `main` 或强制推送。

当前安卓开发分支是 `Android`（2026-09-08 起）；GitHub 默认展示 `main` 时不会显示开发分支的最新内容，应切换分支查看。窗口换模型不改变 Git 分支，也不自动上传提交。交接记录注明上次已确认上传的提交；本轮提交及推送结果在最终回复记录，避免为了自引用提交不断产生新提交。

## 平台分支约定

安卓相关窗口统一使用 `Android`，iOS 后续工作使用 `IOS`，稳定成果经明确安排才合并 `main`。旧 `codex/ios-ui-redesign-demo` 保留历史，不再接收日常开发提交。两条新开发分支从同一完整仓库快照建立；其中 iOS 文件与最后 iOS 提交 `bef808b` 一致，保留安卓参考内容不表示安卓已验收。

开始任务核对分支、工作区和 upstream；不要执行历史提示词中的旧分支指令。使用同一目录的各窗口串行工作，切分支前确认其他窗口空闲；同时开发两端时使用独立 worktree。每次完成后提交、推送对应同名分支并核对远程，默认不操作 `main`。
