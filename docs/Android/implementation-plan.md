## 模型与思考档位建议

这是项目工作建议，不是模型能力的固定换算或正确性保证。默认采用 Astra 低进行日常讨论，正式跨模块分析和阶段审查采用中；Terra 常规实施采用中。用户在对应窗口实际选择档位，提示词不代表设置已生效。

| 模型 | 思考档位 | 适用任务 |
| --- | --- | --- |
| Astra | 低 | 日常讨论、解释已有方案、交接整理和明确任务拆分 |
| Astra | 中 | 多模块分析、架构决策、跨端差异和阶段性代码审查 |
| Astra | 高 | 难定位错误、数据一致性、复杂通知并发和重大方案取舍 |
| Terra | 低 | 范围小且规则明确的文案、颜色、间距等修改 |
| Terra | 中 | 工程初始化、常规页面、表单、业务规则、测试及一般功能实施 |
| Terra | 高 | 数据库迁移、事务回滚、通知调度、复杂状态协调及反复失败的修复 |

选择理由应说明任务的歧义、关联范围和出错影响。高档不能弥补缺失的用户决定，也不能替代测试。反复失败时先整理错误、复现和已尝试方法，判断原因，再建议升档；没有依据时不一律升高，也不长期让低档承担所有功能。

Luna 仅在已有独立、明确的小任务时使用，不为凑齐角色增加窗口。建议和实际使用情况分开记录，未获得实际设置证据时写“未核实”，不推断服务商是否正确应用参数。

## 每次交给执行窗口的任务格式

```text
任务编号与阶段：
角色：执行；仅实施本次范围。
建议模型／思考档位：
选择理由：
目标及对应 A 编号：
代码基准／当前分支：
必读文档与参考源码：
允许修改的路径：
已确认决定及不能自行决定的差异：
验收场景和需要运行的检查：
交付：修改摘要、相关测试及结果、提交编号、限制和下一步。
先检查 Git 状态，保留已有改动；按任务约定由执行或分析窗口更新交接记录。
```

任务应覆盖一个能独立检查的结果，提供相关上下文，不反复复制整个聊天。执行窗口有疑问时，先核对文档与代码，再把影响范围的未决事项交回分析窗口。

## 人工协作流程

1. 分析窗口读取最新交接和实际代码，在最终回复末尾直接提供完整任务交接块；用户只需复制到执行窗口。
2. Terra 实施、验证并提交，在最终回复末尾提供已填好提交和验证结果的审查交接块。交接记录默认由 Astra 审查时维护；任务另有授权则由执行窗口更新。Luna 仅按需承担独立小任务，同一工作区不同时写入。
3. 用户复制该块到当前可用的 Astra；分析窗口自行定位文档，审查实际 diff 和证据，记录问题或审查结论。
4. 执行窗口修正后重新验证；由用户确认产品验收，不用模型自述代替。
5. 切换官方／中转站前停止或完成正在运行的任务，保存交接；接手窗口先核对现场再继续。窗口名称不绑定服务配置，不承诺跨服务恢复旧会话。

## Terra 完成后的审查与推进

用户可以说“Terra 执行完毕，请审查”。建议附任务编号、提交编号（多个提交提供范围）和执行结果摘要。未提供时，分析窗口先从当前仓库和交接记录定位；无法唯一确定范围时再询问，不把最新一个提交自动视为整个实施结果。

分析窗口检查实际 diff、任务验收条件、测试及构建证据、遗留限制和已有改动。必要时执行相关验证；只读到测试源码或执行者自述不能等同于独立验证。审查结束记录范围、结论和下一步：

- 有问题：提供可复制的修正提示词及建议模型／档位。
- 证据不足：列出待验证项，不能将任务标记为已通过。
- 审查通过且无阻塞：给出下一项实施提示词，仍由用户复制到 Terra 后执行。
- 涉及待定产品决定或范围变化：说明具体影响，先解决决定，再生成依赖该决定的任务。

审查一个任务通过，不代表整个 P1 或产品验收完成；下一项可能仍属于当前阶段。Astra 不自动实施、不自动委派，也不因一句“执行完毕”跳过审查。

推荐回传模板：

```text
Terra 已完成任务：
提交编号／范围：
执行结果与测试摘要：
未完成项或限制：
实际模型／档位（如已知）：
请核对代码和证据并审查；有问题给修正提示词，通过后给下一项提示词，不修改应用代码。
```

## 防止状态失真

- “已实现”需要代码依据，“已验证”需要命令／设备与结果，“已审查”需要审查范围；三者不自动推出“用户已验收”。
- 文档所列命令不等于已经执行。失败、未运行、环境不具备分别记录。
- iOS 基准后续变更、发现缺陷、范围增减和协议决定应在功能清单及交接中同步更新。

## 最终回复中的直接交接规则

用户不负责阅读代码、查找文档中的提示词或整理结果。上文任务格式与下列模板供模型填写，不应把空白模板发给用户。需要转交时，最终回复先用中文简述结果，末尾只放一个完整交接代码块；块外写清“复制给 Astra”或“复制给 Terra”及建议档位。不同时给多个竞争任务块，不只说“提示词在 handoff 中”。

模型应填入实际任务、提交或范围、相关文件与验证情况，不保留 `XXXX` 或待用户填写的占位符。未运行、未提交、未知实际模型设置等情况如实标注。不要重复整段历史，把详细依据留在仓库供接手模型读取。说明文档使用中文；技术名称、代码标识和命令可保留原文。
