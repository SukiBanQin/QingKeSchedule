## 实际代码基准

### Android 当前能力

- `domain/ScheduleData.kt` 已有 `Semester`、`Period`、`Course`、`CourseSchedule` 和
  `RepeatRule`，可作为草稿转换的已有领域边界。
- `ScheduleValidator` 已覆盖学期名称、日期、1—52 周、1—20 节、节次时间，以及课程名称、
  颜色、星期、节次和周次范围；草稿不应复制一套会漂移的基础校验。
- `ScheduleRules` 已有教学周和单双周规则，但尚无节次范围重叠、共同生效周及课程冲突
  结果。P2-03 需要补足这部分纯领域能力。
- P2-01 的 `ScheduleAppState` 和 Room 仓库已能在保存学期时连同现有课程整体校验；
  P2-03 不再实现第二套持久化或状态容器。

### iOS 对照基准

行为依据为 `ios/QingKeSchedule/Features/CourseDraft.swift`、`SemesterDraft.swift`、
`ios/QingKeSchedule/Domain/ScheduleRules.swift`、`CourseEditorView.swift`、`SemesterFormView.swift`，

## 可实施契约

### 课程草稿

- 建立不依赖 Android `Context`、Compose 或 Room 的 `CourseDraft` 和
  `CourseScheduleDraft`（或等价命名）。草稿只存于内存，不另外写入 Room 或 DataStore。
- 新建课程默认名称／教师／教室为空，颜色为 `#287B74`，有一个上课安排。安排默认为
  传入本地日期的星期、学期第一个节次、1 至学期总周数、`EVERY`和空教室。
- 创建课程、草稿安排的 ID 生成器以及“今天”必须可注入，测试不依赖随机 UUID、
  系统时钟或主机时区。Kotlin 实现优先使用 `LocalDate`，星期保持周一为 1、周日为 7。
- 编辑已有课程时保留课程／安排 ID 和列表顺序。“为已有课程追加安排”需继承课程资料，
  只新增一个使用当天／首节／整学期默认值的安排，且立即为 dirty。
- 转换为 `Course` 时只去除课程名称、教师和每个教室的首尾空白；颜色和其他字段
  保持候选值，再交由现有 `ScheduleValidator` 校验。`isDirty` 比较规范化后的候选课程与
  初始基线，仅输入会被去除的外围空白不应造成虚假 dirty。
- 新增安排可复制指定安排；未指定时复制最后一项，空列表防御值为周一、第 1 节、
  第 1 周、`EVERY`和空教室。新项必须使用新 ID。删除安排后至少保留一项。

### 重复安排与冲突评估

- 保存评估结果分为 `Invalid(issues)`、`Conflicting(conflicts)` 和 `Ready`（或等价密封
  类型）。顺序必须是：先用现有 `ScheduleValidator` 校验只包候选课程的学期聚合，再检查
  同课程新增完全重复安排，最后计算跨课程冲突。无效数据不同时发布冲突结果。
- “完全重复”特征不包含安排 ID，包含星期、起止节次、起止周、单双周和去除首尾空白的
  教室。候选特征计数大于 1 且超过编辑基线同特征计数时，以路径
  `courses.0.schedules` 和消息“该上课安排已存在，请勿重复添加”阻止保存。
- 已存在的历史重复安排在数量没有增加时仍可编辑保存；不得藉 P2-03 收紧 P1／P2-01
  已接受的重复 ID 或历史数据边界。重复规则不同或教室不同不算完全重复。
- 课程冲突同时满足：星期相同，闭区间节次范围相交，且起止周／单双周存在至少一个共同
  生效的教学周。共同周按升序返回，单周与双周不冲突。
- 冲突结果包含候选课程／安排、已有课程／安排和共同周。对候选安排、已有课程和已有
  安排按输入顺序稳定遍历；与候选课程 ID 相同的已有课程不与自身冲突。
- `Conflicting` 只表示页面后续需要用户确认，不是持久化失败。P2-03 不实现“仍然保存”
  按钮或对话框，也不自动调用 `ScheduleAppState.saveCourse`。

### 学期草稿

- 建立纯 Kotlin `SemesterDraft` 和 `PeriodDraft`。本地日期使用 `LocalDate`，节次时间使用
  `LocalTime`，草稿列表 ID 可注入；转为领域对象时使用 `yyyy-MM-dd` 和 `HH:mm`。
- 新学期默认名称为“`<年份> 春季学期`”或“`<年份> 秋季学期`”；月份小于 7 为春季，
  7 月起为秋季。开始日期为传入的当天，总周数 18，学期 ID 使用可注入生成器。
- 默认十节时间依次为：`08:00–08:45`、`08:55–09:40`、`10:00–10:45`、
  `10:55–11:40`、`14:00–14:45`、`14:55–15:40`、`16:00–16:45`、
  `16:55–17:40`、`19:00–19:45`、`19:55–20:40`。
- 编辑已有学期时保留学期 ID、日期、总周数、节次顺序和时间。学期名称转换时去除首尾
  空白；输出的节次编号按当前列表位置重新生成为 1…n。
- 新增节次以最后一节的结束时间加 10 分钟为开始，再加 45 分钟为结束；空列表防御基准为
  `07:50`。删除后重新连续编号，并且至少保留一节。时间跨日或增加到超过 20 节时不静默
  截断，由现有校验器报错。
- 学期草稿校验将候选学期放入课程列表为空的版本 1 聚合，复用 `ScheduleValidator`。
  缩短学期或删除节次后与已有课程的兼容性，仍由 P2-01 已有仓库／状态在真正保存时对
  完整聚合校验；不在草稿内复制现有课程数据或改变回滚语义。

## 明确不包含

- 不修改 `MainActivity`，不实现 Compose 课程／学期页面、颜色选择器、节次展开状态、错误

- 不修改 Room schema，不新增 DataStore 字段，不改变 `ScheduleAppState` 或仓库一致性契约，
  不持久化表单草稿。
- 不实现教学日历展示、通知调度、权限、导入导出、分享或发布，不决定 D01、D03
  或正式发行范围。
- 不修改 iOS、Web、共享 schema／fixtures，不自动进入 P3 或其他未授权子任务。

## 测试与验收边界

### JVM 单元测试

- 固定 `LocalDate`、ID 序列和学期，验证新课程的当天星期、首节、整学期、默认颜色和
  一个安排；名称／教师／教室规范化及基础校验结果。
- 课程编辑保留 ID，未变更结果非 dirty，被规范化的外围空白不产生虚假 dirty；追加安排
  继承课程资料、使用新 ID 且为 dirty。
- 复制／删除多安排、最少一项保护；新课程重复、追加重复、编辑成重复、历史重复不增加
  可保存，以及不同单双周／教室不算完全重复。
- 冲突覆盖星期、闭区间节次相交、周次边界、`EVERY`／`ODD`／`EVEN`、共同周升序、
  编辑自身排除，并验证结果数量与输入顺序。
- 固定春季／秋季日期验证学期默认名称、18 周和完整十节时间；编辑保留学期值、
  名称去空白，增删节次后连续编号，至少一节，以及新节次的 10／45 分钟规则。
- 复用现有校验器验证空学期名、周数、节数、无效／重叠时间和无效课程安排。现有
  Room 用例继续证明学期缩短／删节导致现有课程无效时整次保存被拒绝且旧数据保留。
