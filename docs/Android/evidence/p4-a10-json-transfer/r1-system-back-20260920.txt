# P4／A10-R1 系统返回修正：设备与自动化证据（2026-09-20）

执行窗口：DeepSeek V4.1 FLASH（实施、自测、设备证据、文档、提交、推送）。实际模型标识／服务／思考参数以
用户客户端为准，本窗口无法读取，未核实。R0 的完整证据见同目录 `device-verification-20260920.txt`，
本文件只记录 R1 的系统返回修正。

## 1. 修改点

`Android/app/src/main/java/com/qingke/schedule/ui/QingKeApp.kt` 的 `TransferDialogHost`：

- 新增 `BackHandler(enabled = transfer.showsPrompt)`：只有传输提示（预览、解析失败、导出失败、可重试写入
  失败）确实可见时才注册，因此不影响 SAF 文件面板、课程编辑器、学期保存弹窗和普通页面返回。
- `isWriting == true` 时回调只消费返回，不调用 `dismissTransferPrompt()`、不调用 `confirmImport()`、
  不取消事务；事务结束后仍沿用既有成功／失败状态。
- 非写入态时返回与对应「取消／好／知道了」一致：只调用一次 `dismissTransferPrompt()`，停在原页面。
- `TransferUiState.showsPrompt` 是唯一可见性判定，同时驱动弹窗渲染与返回注册，避免两者漂移。

自动化设备测试确定性证明。

## 3. 自动化设备测试（真实系统返回事件，API 37 ARM64）

`DataTransferSectionTest` 用 `androidx.test.espresso.Espresso.pressBack()` 注入真实系统返回事件（与仓库既有
时间选择器返回测试同一机制），在 `emulator-5554` 上运行：

| 测试 | 断言要点 |
| --- | --- |
| `aVisiblePreviewGivesSystemBackToTheCancelActionOnceAndKeepsThePage` | 可取消态返回只调用一次 `dismissTransferPrompt`（1 次）、调用 `confirmImport` 0 次、弹窗消失、`main-shell`／`settings-transfer-section` 仍在、`activity.isFinishing == false` |
| `anImportFailureAndARetryableWriteFailureAlsoGiveSystemBackToTheirCancelAction` | 解析失败态与可重试写入失败态各只调用一次 dismiss（累计 2）、confirm 0 次、弹窗消失、页面仍在、Activity 未结束 |
| `aWritingPreviewConsumesSystemBackWithoutCancellingOrLeavingTheActivity` | `isWriting` 时返回后 confirm 0 次、dismiss 0 次、预览弹窗仍显示、两个按钮仍 `assertIsNotEnabled`、`main-shell` 仍在、Activity 未结束 |
| `theBackContractStaysOffWhileNoTransferPromptIsVisible` | 没有传输提示时（仅有成功状态）返回仍交给课程编辑器的 `editorBack` 1 次，dismiss／confirm 0 次，Activity 未结束（证明未注册或未被启用的 BackHandler 不会抢占其他层的返回） |
| `thePreviewScrimStillBlocksTouchesToThePageBehindIt` | 预览可见时对弹窗后「从 JSON 文件导入课表」坐标做真实触摸，`requestImport` 0 次、弹窗仍在、Activity 未结束（保留遮罩回归） |

结果：`DataTransferSectionTest` **15 tests、0 failures／0 errors／0 skipped**（R0 为 10，R1 新增 5）。
完整设备集合与其余回归命令见 `verification-commands-20260920.txt` 的 R1 小节。
