1. **iOS App 真实 UI 往返未执行。** 尝试在沙箱内构建并运行未修改的 `origin/IOS`
   UI 测试 `QingKeScheduleUITests/testValidImportPreviewCancelConfirmAndExportEntry`
   （`xcodebuild test -project QingKeSchedule.xcodeproj -scheme QingKeSchedule
   -destination 'platform=iOS Simulator,name=iPhone 17,OS=27.0' -derivedDataPath /tmp/ios-a10-derived
   -only-testing:...`，并把 `TMPDIR`／`SWIFT_MODULE_CACHE_PATH`／`CLANG_MODULE_CACHE_PATH` 指到可写目录）：
   编译在此环境失败 1068 处，全部为
   `external macro implementation type 'SwiftUIMacros.StateMacro' could not be found for macro 'State()'; '.../swift-plugin-server' produced malformed response`
   （`ObservationMacros.ObservableMacro` 同类）。属于本会话沙箱对 Swift 宏插件进程的限制，不是 iOS 代码缺陷。
   因此 iOS 侧往返使用**未修改源码的主机编译实现**（见 `ios-source-integrity.txt`），
   iOS 文件 App／ShareLink 的真实 UI 交互仍待在有完整 Xcode 环境的机器上验证。
2. 真实重启、Doze、厂商真机后台行为与通知观感属于 A08 遗留未验证项，本轮不涉及也不改变其状态。
3. 非标准文档 provider（如 MediaStore Downloads）不实现 `rwt` 截断：对**同一** MediaStore 文档写入更短
   内容时会保留旧尾部；标准 `ACTION_CREATE_DOCUMENT` 的 SAF provider 用
   `ParcelFileDescriptor.parseMode("rwt")`（含 `MODE_TRUNCATE`）截断，导出路径实际使用该方式。
   `ScheduleFileAccessDeviceTest.rewritingTheSameDocumentReplacesTheBackupThroughTheRealProviderStream`
   因此只断言真实 provider 能保证的等长／增长重写逐字节替换。

## 6. 环境限制记录（构建命令）

本会话沙箱禁止写 `~/.gradle`，且 Kotlin 守护进程会把含中文的工程路径转义成
`u8BFEu8868u8F6Fu4EF6` 导致 `source file or directory not found`。因此：

- `GRADLE_USER_HOME=/tmp/a10-gradle-home`（`cp -Rc ~/.gradle` 的克隆）。
- 追加 `-Pkotlin.compiler.execution.strategy=in-process` 让编译在 Gradle 进程内完成，避免该守护进程问题。
- 其余命令、源码、变体、设备与测试内容均与仓库常规一致。
