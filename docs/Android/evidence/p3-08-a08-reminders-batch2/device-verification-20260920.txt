P3-08／A08 第二批：提醒设置页与真实流程设备记录（API 37 ARM64，qingke-api37-r3-arm）

环境：emulator-5554（AVD qingke-api37-r3-arm，API 37／arm64-v8a），`wm size 1080x2400`、`density 420`、
`font_scale 1.0`，动画缩放 0。应用为本轮 debug APK，通过 `adb install` + `am instrument` 直接运行，因为
Gradle `connectedDebugAndroidTest` 结束后会卸载应用并清除设备侧证据目录。

## 1. 已授权权限：真实设置页流程（截图 settings-reminders-enabled.png）

```
adb install -r app-debug.apk
adb install -r app-debug-androidTest.apk
adb shell pm grant com.qingke.schedule android.permission.POST_NOTIFICATIONS
adb shell am instrument -w -e class com.qingke.schedule.ui.ReminderSettingsFlowTest \
  -e additionalTestOutputDir /sdcard/Android/media/com.qingke.schedule/additional_test_output \
  com.qingke.schedule.test/androidx.test.runner.AndroidJUnitRunner
-> OK (3 tests)
```

用例用生产 `QingKeApp` + 真实 `ScheduleViewModel`、Room、DataStore、生产协调器与 AlarmManager 断言：

- 打开「03 设置」页的「04 上课提醒」，点击开关后偏好写盘、滚动窗口被登记到 AlarmManager（注册表条目数 ==
  平台可查到 PendingIntent 的条目数），状态行显示「已安排最近 N 条课程提醒」；再点开关后平台闹钟与注册表都
  清空，状态行回到「提醒已关闭」。
- 在页面上选择「提前 30 分」后，注册表里每条闹钟的 `fireAt` 都变成 `startAt - 30 分钟`，`usesCustomLeadTime`
  为 false；选择「自定义…」再点「+」后 `usesCustomLeadTime=true`、分钟数 +1。
- 能力行跟随真实平台状态：通知权限已授权时显示「已授权」；精确闹钟行按 `canScheduleExactAlarms()` 显示
  「可用／不可用」，不可用时给出 D03 说明与「精确闹钟设置」入口（不使用 USE_EXACT_ALARM）。

截图 settings-reminders-enabled.png（974×1601）显示：开关开启、预设「准时／提前 5／10／15／30 分／自定义…」、
通知权限「已授权」、提醒渠道「可用」、精确闹钟「不可用」、D03 说明「精确闹钟不可用，提醒将按非精确方式安排
并在通知里标注「（可能延迟）」。」、状态「已安排最近 2 条课程提醒（部分可能延迟）」与「精确闹钟设置」按钮。

## 2. 预先撤销通知权限：权限拒绝分支（截图 settings-reminders-permission-denied.png）

```
adb shell pm revoke com.qingke.schedule android.permission.POST_NOTIFICATIONS
adb shell appops get com.qingke.schedule POST_NOTIFICATION
-> Uid mode: POST_NOTIFICATION: ignore
adb shell am instrument -w -e qingkePermissionDenied true \
  -e class com.qingke.schedule.ui.ReminderSettingsFlowTest#theCapabilityRowsFollowTheRealPlatformState \
  -e additionalTestOutputDir /sdcard/Android/media/com.qingke.schedule/additional_test_output \
  com.qingke.schedule.test/androidx.test.runner.AndroidJUnitRunner
-> OK (1 test)
adb shell am instrument -w -e class com.qingke.schedule.reminder.ReminderPermissionRevocationTest \
  com.qingke.schedule.test/androidx.test.runner.AndroidJUnitRunner
-> OK (1 test)
```

- 该专门运行通过 `-e qingkePermissionDenied true` 跳过测试自身的授权动作，页面的开关由生产 ViewModel 入口
  驱动（开关本身会拉起系统权限弹窗，自动化运行不依赖该弹窗）。
- 断言：偏好成功写盘、页面显示「通知权限：未开启」与红色状态「系统通知权限未开启，提醒不会投递」，给出
  「开启通知权限」「系统通知设置」两个显式操作，学期／节次表单仍可用（`settings-semester-section` 可见），
  且 AlarmManager 中没有登记任何闹钟——拒绝权限后课表继续正常使用，不循环弹窗。
- 截图 settings-reminders-permission-denied.png（974×1717）显示上述状态。

## 本环境未验证（不得声称通过）

- 真实系统权限弹窗的人工观感（自动化运行只断言拒绝后的界面状态）；
- 真实重启后的 BOOT_COMPLETED 投递、系统投递的受保护广播、Doze／休眠中的精确／非精确真实投递时间；
- 用户可见提醒通知的观感验收（沿用第一批截图与记录）。
