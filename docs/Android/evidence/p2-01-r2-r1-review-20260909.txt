四、P2-01 整体验收差距

实际 Android Room 测试类只有上述 4 个方法。对照 p2-01-persistence-state.md 的 API 37 Room
集成测试契约，尚未有自动化证据覆盖：
- 同一课程的多安排顺序与重复安排 ID 往返。
- saveSemester／saveCourse 的新建、更新、追加与首个重复 ID 语义，以及删除不存在项
  不更新时间。
- 安排随课程删除的数据库外键级联本身；当前从仓库读回快照不能观察不可达的孤儿行。
- 学期变更使现有课程无效、无学期保存课程等所有写入前拒绝与旧数据保留。
- 手工写入缺失元数据、非法重复规则或其他可构造损坏记录后，load 返回损坏错误且不清库。
- 已导出版本 1 schema 且没有 destructive migration 的自动化检查。

状态 JVM 测试也只对 replace 证明成功返回快照和写失败回滚，并只通过并发用例间接
执行 saveCourse；尚未按契约对 saveSemester、saveCourse、deleteCourse、replace 逐一证明
成功发布仓库返回快照且不二次读取，以及每种写失败都保留内存快照。

此外存在一个可确定的生产语义差异：RoomScheduleRepository.read 重建 ScheduleData 后调用
validate；validate 在聚合无效时抛出 ScheduleRepositoryException.InvalidData，随后 read 的
catch (ScheduleRepositoryException) 原样重抛。因此从存储读取到可映射但违反领域校验的记录时，
当前错误类型是 InvalidData，而契约要求识别为 InconsistentStore。
