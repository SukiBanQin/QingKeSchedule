## 首轮独立复审后的修正（基准 `5b18381`，2026-09-14）

首轮实现提交 `5b18381b22ffe6876868395fce2a446083fe7423` 尚未通过 Sol 独立复审，发现以下实际问题：

1. 深色与 130% 字体图中的 Logo 非青色前景仍为黑色，无法辨读。
2. adaptive foreground 引用 `@mipmap/ic_launcher`，在 API 26+ 会回指 adaptive icon 自身，生产 launcher 实际显示默认机器人。
3. `PullToRefreshBox` 和手写 `detectVerticalDragGestures` 并存，可能一条真实手势触发两次刷新。
4. 课程序号没有旋转，且既有截图无法看全 COMPLETE/CURRENT/NEXT/UPCOMING 序列与 END。
5. iOS 两张旧参考停留在首次设置，不能作为同状态 TODAY 的证据。

本轮仅在既有 P3-03-R2 范围内修正：从用户指定的 `source/qingke-logo-q-matrix-preview.png` 机械派生
`drawable-night/qingke_logo.png`，保持透明度和青色块，其他非透明深色前景映射为浅色；`source/` 未改。
`qingke_cover.png` 是 `source/cover.png` 的独立缩放副本，`ic_launcher_foreground.xml` 只引用该 drawable，
不再引用任何 adaptive `mipmap` 名称。资源契约 AndroidTest 读取 foreground XML 并断言独立 cover 引用和 Manifest
应用名“青课”。生产手写拖拽识别已删除，只保留 `PullToRefreshBox(onRefresh = triggerRefresh)`；`refreshing` 在启动协程
前同步置位，测试从真实 `today-scroll-content` 下拉，断言单回调、刷新中不重入以及反馈结束。课程序号以 iOS 相同
方向 `rotationZ = -90f` 绘制，但保留无障碍语义。

iOS 同状态参考已重新取得：在独立、干净的 `IOS` `fc3ddfb8` 工作区执行
`xcodebuild -project ios/QingKeSchedule.xcodeproj -scheme QingKeSchedule -destination 'platform=iOS Simulator,id=D9BB94EF-F2A0-4B6C-B258-822CE8D51AC2' -only-testing:QingKeScheduleUITests/QingKeScheduleUITests/testValidImportPreviewCancelConfirmAndExportEntry test`

在真实导入确认页点击“替换当前课表”后可见 `today-tab`，用 `simctl io ... screenshot` 保存
`ios-fc3ddfb8-today-imported.png`。这张新图才是本次同状态 iOS TODAY 参考；旧 onboarding 图只保留为首轮尝试历史。
