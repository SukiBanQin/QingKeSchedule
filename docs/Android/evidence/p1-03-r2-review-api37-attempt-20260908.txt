P1-03-R2 独立复审 API 37 ARM64 启动诊断（2026-09-08）

本记录属于分析审查证据，不是执行提交 2e5b8ec 的组成部分，也不是设备通过证据。

环境：

- macOS 26.6.2，arm64
- Android Emulator 37.1.11.0
- SDK：/tmp/qingke-api37-sdk-iJNEtV
- AVD：qingke-api37-arm
- system image：system-images;android-37.0;google_apis;arm64-v8a revision 6

只读诊断：

1. emulator-check accel 返回 0，并报告 Hypervisor.Framework OS X Version 26.6。
2. sysctl kern.hv_support 返回 1。
3. libandroid-emu-tracing.dylib 实际存在于 emulator/lib64/。
4. qemu-system-aarch64 为 arm64，签名权限包含 allow-jit、
   allow-unsigned-executable-memory 与 com.apple.security.hypervisor。

独立启动命令的关键参数：

ANDROID_AVD_HOME=/tmp/qingke-api37-avd-2BJSGW \
  /tmp/qingke-api37-sdk-iJNEtV/emulator/emulator \
  -avd qingke-api37-arm -port 5560 -no-snapshot -no-window \
  -gpu software -accel on -verbose

观察：

1. 使用官方 emulator 启动器，而不是直接执行内部 qemu-system-aarch64。
2. 禁用快照、窗口并切换软件图形后，连续 8 次、每隔 5 秒检查均为 adb offline；
   sys.boot_completed 无法读取为 1。
3. 启动日志先确认 CPU acceleration status 为 Hypervisor.Framework OS X Version 26.6，
   随后又报告 hvf is not enabled on this aarch64 host，并反复输出
   qemu_mprotect__osdep: mprotect failed: Permission denied。
4. 达到限定观察时间后只终止本次 5560 启动进程；没有操作既有 API 35 emulator-5554。

用户另提供的桌面截图显示：正常启动窗口同样有 mprotect 拒绝和 DisplaySurfaceGL 创建
失败；macOS 再打开的另一窗口直接运行了内部 qemu-system-aarch64，因没有经过 emulator
启动器设置运行库路径而报告找不到 @rpath/libandroid-emu-tracing.dylib。该动态库实际存在，
所以右侧报错不证明 SDK 缺包，也不属于 APK 或应用代码错误。

结论：复审环境仍不能取得 sys.boot_completed=1。未安装 APK，未执行两次冷启动、
MainActivity resumed/可见、pidof、截图或清空后的应用 logcat。当前证据支持模拟器宿主
运行环境受阻，不能推出应用通过或应用缺陷。
